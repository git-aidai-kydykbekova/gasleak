# Руководство по проекту: как всё устроено и что было сделано

**Проект:** Low-Power Ultrasonic Gas Leak Detection using Dynamic Neuromorphic Event-Based Processing
**Автор:** Aidai Kydykbekova · **Документ обновлён:** 2026-11-07

**Исследовательский вопрос (RQ):** может ли событийная (event-driven) спайковая нейросеть (SNN) снизить энергопотребление датчика в 10 раз в периоды, когда утечки нет?

---

## 1. Идея в двух словах

Утечка газа под давлением даёт турбулентную струю, а она шипит в **ультразвуке** (примерно 25–50 кГц). Почти весь заводской шум (моторы, удары) лежит ниже 20 кГц. Поэтому мы слушаем только ультразвуковую полосу 18–46 кГц.

Почти всё время утечки **нет**. Обычная нейросеть (CNN) всё равно считает каждый кадр каждую миллисекунду и впустую тратит энергию. Идея проекта:

1. Превращать звук в **события (спайки)**, только когда что-то меняется относительно фонового шума.
2. Обрабатывать эти события **спайковой сетью**, которая считает только тогда, когда приходят спайки.

Если вокруг тихо, событий почти нет, значит почти нет и вычислений.

```
  звук 96 кГц ──► фильтрбанк ──► энкодер событий ──► SNN ──► правило тревоги ──► ALARM
  (микрофон)     16 полос,        32 спайковых       LIF64→LIF64    5 мс подряд
                 кадр 1 мс        канала             →readout       выше порога
```

## 2. Как работает каждый блок

### 2.1 Данные: `gasleak/synth.py`, `build_dataset.py`
Открытого набора ультразвуковых записей с утечками **и без утечек** нет. Поэтому основной набор данных синтетический, построенный по упрощённой физике:

- **Утечка:** полосовой шум. Его центральная частота зависит от давления: 24 кГц при низком и 40 кГц при высоком. Есть резкое начало (onset в момент 0.15–0.6 с) и «дрожание» струи (амплитудная модуляция 2–15 Гц).
- **Фон «quiet»:** розовый шум и слабый ультразвуковой шум электроники.
- **Фон «factory»:** гармоники вращающихся машин, тон шестерён, удары (затухающие резонансы до 25 кГц).
- **Ложные цели (hard negatives):** короткие ультразвуковые выбросы сжатого воздуха (10–80 мс) и ультразвуковые тоны импульсных блоков питания.
- **SNR** задаётся именно в полосе 18–46 кГц: −10, −5, 0, 5, 10 или 20 дБ.

`build_dataset.py` генерирует 3000 клипов по 1 с (половина с утечкой) и делит их стратифицированно 70/15/15 (2100 / 450 / 450) по метке × сцене × SNR. Результат: `data/synth/dataset.npz` и `data/synth/meta.csv`.

Для длинных записей без утечки у `make_clip` есть параметры `n` (длина) и `level_db` (уровень фона). Обычные 1-секундные клипы при этом остались **бит-в-бит такими же**: я сравнил 200 клипов со старой версией.

### 2.2 Фильтрбанк: `gasleak/features.py::band_levels_db`
- STFT: окно Ханна 256 отсчётов, шаг 96 отсчётов, то есть **1 кадр = 1 мс**.
- 16 полос, логарифмически распределённых в диапазоне 18–46 кГц. Мощность полосы сглаживается EMA (τ = 4 мс) и переводится в дБ.
- Результат: матрица `[время, 16 полос]` в дБ.

### 2.3 Энкодер событий: `encode_events`
Он работает как улитка уха, у которой есть клетки «устойчивого» сигнала и клетки «начала» сигнала. Для каждой полосы:

1. **Трекер уровня шума (noise floor):** медленная EMA (τ = 2 с). Она обновляется только пока сигнал близок к шуму и **замораживается**, когда сигнал выше.
2. **Превышение:** `e = max(0, L − floor − 3 дБ)`.
3. **Канал SUSTAINED** (integrate-and-fire): `e` накапливается, и при сумме ≥ 6 выдаётся спайк. Чем сильнее сигнал над шумом, тем чаще спайки.
4. **Канал ONSET** (дельта-модулятор): спайк, когда `e` вырос на ≥ 1.5 дБ.

16 полос × 2 канала = **32 входа SNN**. Стационарный фон любой громкости даёт `e ≈ 0` и почти ноль событий: в тихом клипе около 3 событий за секунду, а при утечке с SNR 0 дБ около 3100.

### 2.4 Спайковая сеть: `gasleak/models.py::LeakSNN`
- Архитектура: 32 входа → **LIF(64)** → **LIF(64)** → интегрирующий выход (1 нейрон).
- Нейрон LIF (как в snnTorch, сброс вычитанием):
  ```
  reset = (mem_prev > 1)
  mem   = β·mem_prev + I − reset·1       (β обучается, ≈ 0.9)
  spike = (mem > 1)
  ```
- Выходной нейрон без сброса: `m3 = β3·m3 + I3`, `logit = m3 + bias`. Это вероятность утечки на каждой миллисекунде.
- Обучение спайков идёт через суррогатный градиент (fast sigmoid).

### 2.5 Базовые модели
- **CNN (always on):** причинная 1-D CNN с дилатацией (3 слоя по 32 канала, ядро 9, дилатации 1/2/4, рецептивное поле 57 мс). Работает на плотных уровнях полос каждую миллисекунду.
- **Dense twin:** та же SNN, но посчитанная «по кадрам» (все веса каждый шаг). Показывает, сколько даёт именно событийность.
- **CNN event-gated** (новое): та же CNN, но она **просыпается только когда энкодер выдал событие** за последние 100 мс, а в остальное время спит. Это честный конкурент: обычно так и строят маломощные детекторы (дешёвый триггер плюс тяжёлая сеть по требованию).

### 2.6 Обучение: `train.py`
- Цель на каждом шаге: 0 до начала утечки и 1 после него. Первые 30 мс после onset не штрафуются (детектору нужно немного накопить сигнал).
- Функция потерь: BCE плюс слабая регуляризация числа спайков. Оптимизатор Adam, lr = 2e-3, косинусное расписание. Сохраняется модель с лучшей валидационной ошибкой.
- Новые параметры: `--seed` (инициализация и порядок батчей; разбиение данных фиксировано), `--out` (по умолчанию `runs/seeds/<seed>/`), `--threads`.
- `run_seeds.sh` обучает 5 сидов: 5 SNN параллельно по 1 потоку (циклу по времени потоки не помогают) и CNN по очереди на оставшихся ядрах. Это около 40 минут на 8-ядерном CPU.

### 2.7 Правило тревоги и метрики: `gasleak/metrics.py`
- **Тревога:** logit выше порога τ **5 мс подряд** (K = 5). Первые 100 мс не учитываются: энкодер ещё учит уровень шума.
- **Ложная тревога** — тревога в любом **отрезке без утечки**: в клипе без утечки или в части клипа с утечкой **до её начала**. Раньше вторая часть терялась, `pre_alarm` вычислялся, но не использовался.
- **Сравнение при одинаковой доле ложных тревог (matched FA):** для каждой модели порог подбирается на **валидации** так, чтобы ложных тревог было ≤ 1 % или ≤ 5 %, и при этом пороге модели сравниваются на **тесте**. Раньше SNN работала при 1.3 % FA, а CNN при 6.2 %, так что сравнение было нечестным.
- **DET-кривая:** доля пропусков против доли ложных тревог при всех порогах.
- **Задержка обнаружения:** время тревоги минус время начала утечки (медиана, среднее, p90).
- **Неопределённость:** среднее ± std по 5 сидам и **95 % доверительные интервалы** бутстрепом (пересэмплируются и сиды, и тестовые клипы) для recall и FA, отдельно для каждого SNR.

### 2.8 Модель энергии: `gasleak/energy.py`
Это **оценка**, а не измерение. Энергия операции в 32-битной арифметике на 45 нм (Horowitz 2014): умножение 3.7 пДж, сложение 0.9 пДж.

| Блок | Что считается | Мощность |
|---|---|---|
| **Фронтенд** (общий для всех) | окно, FFT на 256 точек каждую 1 мс, \|Z\|² 75 бинов, суммы полос, EMA, log10 ≈ 2630 умножений + 3366 сложений на кадр | **≈ 12.8 мкВт** |
| Энкодер событий | трекер шума + 2 спайковых канала × 16 полос | ≈ 0.26 мкВт |
| SNN, clock-driven | 1 сложение на синаптическое событие + обновление всех 129 нейронов каждый шаг | ≈ 0.9 мкВт в тишине |
| SNN, event-driven | нейроны слоя обновляются только когда в слой пришли спайки (нижняя граница) | ≈ 0.4 мкВт в тишине |
| Dense twin | вся матрица весов каждый шаг | ≈ 29.4 мкВт |
| CNN always on | 27.6 тыс. MAC на кадр | ≈ 127.5 мкВт |
| CNN event-gated | CNN × доля времени бодрствования + пересчёт рецептивного поля при каждом пробуждении | зависит от числа событий |

Не учтены: доступ к памяти, АЦП, микрофон, статическое потребление MCU. **Реальные мВт можно получить только измерением на плате.**

### 2.9 Длинные записи без утечки: `quiescent.py`
RQ спрашивает именно про **периоды без утечки**, поэтому есть отдельный эксперимент. Для каждого условия генерируется 5 записей по 60 с, которые без сброса прогоняются через все детекторы:
- тихое помещение;
- завод с фоном −28, −20 и −12 дБ;
- **завод −20 дБ со скачком +10 дБ на середине** (например, включилась машина).

Результат: события в секунду, **ложные тревоги в час**, доля времени в тревоге и мощность каждого конвейера (`runs/quiescent.csv`, `runs/figs/quiescent.png`).

### 2.10 Железо: ESP32-S3 и онлайн-симулятор Wokwi: `firmware/`
- **`leak_snn.h`** — SNN на чистом C++ без зависимостей. Она работает **событийно**: на каждом шаге складываются только столбцы весов тех входов, которые выдали спайк. Есть и плотный режим `step_dense` для сравнения. Уравнения точно повторяют snnTorch.
- **`export_firmware.py`** выгружает веса обученной модели и 6 тестовых клипов (тишина, завод, утечки с SNR 20, 0, −5 и −10 дБ) вместе с эталонными выходами PyTorch в C-заголовки.
- **`sketch.ino`** — демо для ESP32-S3. Оно проигрывает спайковые потоки в реальном времени (1 шаг = 1 мс): красный светодиод означает тревогу, зелёный — что всё в порядке, кнопка переключает запись. В Serial выводится:
  - обнаружена ли утечка и с какой задержкой;
  - **совпадает ли тревога с PyTorch**;
  - сколько микросекунд CPU занят на каждом миллисекундном шаге в событийном и в плотном режиме.
- **`diagram.json`** — схема для Wokwi (ESP32-S3 DevKitC-1, 2 светодиода, кнопка). Инструкция: [firmware/README.md](../firmware/README.md).
- **`host_test.cpp`** — тот же C++ код, собранный на ПК и проверенный против PyTorch.

## 4. Предварительные результаты (старая модель, 1 сид, новая методика)
> ⚠️ Это **не финальные цифры**. Это результат smoke-теста: старый чекпойнт `runs/snn.pt` / `runs/cnn.pt`, прогнанный через новую оценку. Финальные числа появятся после `./run_seeds.sh` → `evaluate.py` → `quiescent.py`.

**Качество при одинаковой доле ложных тревог (тест, 450 клипов):**

| Детектор | Recall @ FA 1 % | Задержка (медиана) | Recall @ FA 5 % | Задержка | Recall при −10 дБ @ 5 % |
|---|---|---|---|---|---|
| SNN | 0.889 | 70 мс | 0.907 | 46 мс | 0.46 [0.31–0.62] |
| CNN always on | 0.982 | 61 мс | 0.991 | 39 мс | 0.97 |
| CNN event-gated | 0.973 | 60 мс | 0.987 | 37 мс | 0.95 |

**Мощность без утечки (оценка, мкВт, включая фронтенд):**

| Условие | SNN clock | SNN event | Dense twin | CNN always on | CNN gated |
|---|---|---|---|---|---|
| тишина | 13.9 | 13.4 | 42.4 | 140.4 | 49.0 |
| завод | 14.0 | 13.5 | 42.4 | 140.4 | 86.4 |

**Что это значит для RQ:**
- Против CNN, которая работает всегда, выигрыш **≈ 10.1x**, ровно на границе 10x.
- Против честных конкурентов выигрыш **≈ 3–6x**: CNN с пробуждением 3.5x в тишине и 6.2x на заводе, dense twin около 3x.
- Если считать только нейросеть, выигрыш 30–145x. Но **92 % мощности SNN-конвейера уходит на фронтенд (FFT).** Чтобы честно получить 10x, нужно удешевить именно фронтенд: заменить FFT дешёвым триггером по энергии или аналоговым фильтрбанком.

**Другие находки:**
- **Скачок фона на +10 дБ** даёт тревогу примерно в половине всего времени у всех детекторов (короткий тест, 3 с × 2). Трекер шума «замерзает», когда сигнал выше уровня шума, и больше не адаптируется к новому фону. Это нужно исправить: например, разрешить медленную адаптацию вверх.
- **SNN не молчит без входа.** В тихом клипе 3 входных события, но около 27 синаптических операций на шаг: нейроны первого слоя спайкуют от смещения (bias). Регуляризация bias сделает тишину по-настоящему тихой.
- При −10 дБ CNN с пробуждением находит 95 % утечек. Значит, у энкодера всё-таки есть события, и слабое место скорее в самой SNN, а не только в энкодере.

## 5. Как запустить всё

```bash
source .venv/bin/activate
python build_dataset.py                 # если нет data/synth/dataset.npz
./run_seeds.sh                          # обучение 5 сидов (~40 мин)
python evaluate.py                      # метрики, CI, DET, энергия, пороги
python quiescent.py                     # длинные записи без утечки (~15 мин)
python export_firmware.py               # новая модель -> заголовки для ESP32-S3
c++ -O2 -std=c++17 firmware/host_test/host_test.cpp -o host_test && ./host_test
```
Затем откройте Wokwi по инструкции в [firmware/README.md](../firmware/README.md).
