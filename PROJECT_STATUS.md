## 2. What has been completed

### 2.1 Synthetic ultrasonic dataset: `gasleak/synth.py`, `build_dataset.py`
- 3,000 clips, 1 s at 96 kHz, balanced between leak and no-leak.
- Leak model: turbulent-jet hiss whose peak frequency depends on pressure (24–40 kHz), with a sudden start (onset at 0.15–0.6 s) and flutter.
- Noise model: two scenes, *quiet* and *factory*. Factory noise includes machine harmonics, gear mesh and impacts. Hard negatives include ultrasonic air bursts and ultrasonic tones.
- SNR is controlled in the 18–46 kHz band: −10, −5, 0, 5, 10 and 20 dB.
- Stratified 70/15/15 split (2,100 / 450 / 450 clips) by label × scene × SNR. Saved in `data/synth/meta.csv`.

### 2.2 Event-driven front-end: `gasleak/features.py`
- 16 log-spaced ultrasonic bands (18–46 kHz), 1 ms frames.
- Noise-floor tracker per band. The tracker freezes while a signal is present.
- 2 spike channels per band (32 inputs): *sustained* (integrate-and-fire on the level above the floor) and *onset* (delta modulator).
- Shown to be quiet in practice: a quiet no-leak clip gives about **3 events/s**, while a 0 dB leak gives about 3,100 events/s (`runs/figs/event_raster.png`).

### 2.3 Models: `gasleak/models.py`
- `LeakSNN`: 32 → LIF(64) → LIF(64) → leaky readout. Betas are learnable and the surrogate gradient is fast-sigmoid. It outputs a leak probability at every 1 ms step.
- `CausalCNN`: a dilated causal 1-D CNN on dense band levels. This is the always-on baseline.

### 2.4 Training: `train.py`
- Per-time-step BCE loss with a 30 ms grace window after onset, plus a spike-sparsity regulariser, cosine learning rate and best-on-validation checkpointing.
- Trained: SNN for 25 epochs, CNN for 40. Logs and histories are in `runs/`. Checkpoints are `runs/snn.pt` and `runs/cnn.pt`.

### 2.5 Evaluation: `evaluate.py` (synthetic test set, 450 clips)

| Metric | SNN | CNN |
|---|---|---|
| Recall | 0.884 | 0.991 |
| Precision | 0.985 | 0.941 |
| F1 | 0.932 | 0.965 |
| False-alarm rate | **1.3 %** | 6.2 % |
| Median / p90 detection delay | 72 / 178 ms | 46 / 70 ms |
| Recall at −10 dB SNR | **0.33** | 0.97 |
| Recall at ≥ −5 dB SNR | 1.00 | ≥ 0.975 |

Estimated compute power (`runs/energy.csv`, 0.9 pJ per accumulate (AC) and 4.6 pJ per multiply-accumulate (MAC), Horowitz 2014):

| Condition | SNN | Same net, dense | CNN | CNN / SNN |
|---|---|---|---|---|
| No leak, quiet | 0.057 µW | 28.6 µW | 127 µW | 2,236x |
| No leak, factory | 0.121 µW | 28.6 µW | 127 µW | 1,051x |
| Leak active | 0.69 µW | 28.6 µW | 127 µW | 184x |

Figures: `runs/figs/snr_robustness.png`, `runs/figs/energy.png`, `runs/figs/event_raster.png`.

### 2.6 Real-data check: `gpla12_experiment.py` (GPLA-12, 684 clips, 12 classes)
- Level-crossing encoder (8 levels × ON/OFF), SNN compared with a 1-D CNN on the raw signal.
- Test accuracy: **SNN 83.5 %** (macro-F1 0.817) vs **CNN 82.5 %** (macro-F1 0.806).
- Synaptic operations (SynOps): 0.76 M per clip for the SNN vs 8.6 M multiply-accumulates (MACs) for the same network run densely.

## 4. Problems found in the current results (fix these first)

### 4.1 The 10x claim omits the front-end, which dominates power
The README states that the filterbank is *not* included. A rough count for one 256-point FFT, the magnitude step and the band sums every 1 ms gives about 3–5 k operations per frame, which is about **15–25 µW** at the same per-operation energies. That is about 300x more than the SNN's 0.057 µW. Once it is added to both sides:

- SNN ≈ 0.06 + ~20 = **~20 µW**
- Dense twin ≈ 28.6 + ~20 = ~49 µW, giving **about 2.5x**
- CNN ≈ 127 + ~20 = ~147 µW, giving **about 7x**

So the 10x result is **not yet shown** at the system level. Before claiming it, count the front-end in `evaluate.py`, or change the front-end so it also runs only on events (see 5.2).

### 4.2 The baselines are too easy to beat
An always-on CNN is not the system people actually build. The usual design is an **energy-threshold wake-up followed by a CNN** (duty cycling). When no leak is present, that design also costs very little. The RQ needs this baseline, or a reviewer will reject the 10x claim.

### 4.3 SNN and CNN are compared at different false-alarm rates
`pick_tau` could not reach FA ≤ 5 % for the CNN on validation and fell back to τ = 0.98, so the test FA is 6.2 %. The SNN runs at 1.3 % FA. Recall and delay are therefore not comparable. Report **DET/ROC curves**, and recall and delay at a matched FA rate (for example 1 % and 5 %).

### 4.4 False alarms on leak clips before onset are ignored
`score()` computes `pre_alarm` but never uses it. An alarm before the leak starts is not counted as a false alarm, so the reported FA rate is too low for both models.

### 4.5 The SNN fails at −10 dB SNR
Recall is 0.33 for the SNN vs 0.97 for the CNN. The likely cause is the encoder: `margin_db=3.0` means a leak below the noise floor never produces spikes, so the SNN never sees it. "High ambient noise" is the core objective, so this is the main weakness in accuracy.

### 4.6 There is no statistical confidence
Each SNR bin has only about 37 test clips, everything uses one seed and one split, and there are no confidence intervals. On GPLA-12 the SNN–CNN gap (83.5 % vs 82.5 %) is **one test clip out of 103**, so the result is a tie, not a win.

### 4.7 The GPLA-12 encoding is not sparse
On average 1,214 events are produced for 1,460 time steps, so nearly every step has an event. The sparsity argument does not carry over to this encoding.

### 4.8 Reproducibility
- There is no `requirements.txt` with pinned versions.
- `data/synth/dataset.npz` is not in the repo. It can be regenerated, so this is fine, but document it.
- `.idea/` is committed and there is no top-level `.gitignore`.
- There are no tests.

## 5. What to add, build or implement (in priority order)

### Priority 1: Answer the RQ honestly (software only, about 1 week)
1. **Count the front-end energy** in `evaluate.py`: FFT, |·|², band sums, EMA and the encoder, for both pipelines.
2. **Add a wake-up + CNN baseline**: a band-energy threshold that wakes the CNN, with power = always-on detector + duty cycle × CNN.
3. **Add matched-FA evaluation**: DET curve, and recall and delay at FA = 1 % and 5 %. Count pre-onset alarms as false alarms (4.4).
4. **Run 3–5 seeds** and report mean ± std, plus bootstrap 95 % confidence intervals for each SNR bin.
5. **Add a quiescent-only experiment**: long (60 s or more) no-leak recordings at several factory loudness levels, reporting events/s, SynOps/s and µW. This is the condition the RQ asks about.

### Priority 2: Improve robustness in noise
6. Make the encoder thresholds adaptive or learnable (`margin_db`, `theta_sus`, `theta_on`), and run an ablation to show how each affects recall at −10 dB and the quiet-state event rate.
7. Add noise types the generator does not have yet: compressor tonal ultrasonics, steam traps, rain on pipes, other leaks far away.
8. Augment with real background noise, for example by mixing GPLA-12 "strong noise" clips or public factory-noise recordings into the synthetic set.
9. Optional: an adaptive front-end that runs only on events (an analog-style bandpass filterbank with level-crossing events, or a cheap always-on energy detector that wakes the FFT). This is what makes the system-level 10x possible (4.1).

### Priority 3: Hardware (the largest missing piece in the proposal)
10. **Ultrasonic sensor**: an ultrasonic-capable MEMS microphone such as a Knowles SPU0410LR5H-QB / SPH0641LU4H, or an analog ultrasonic transducer with a preamp. Check the datasheet bandwidth reaches 40 kHz or more.
11. **ESP32-S3 firmware (C++, ESP-IDF)**: I2S or ADC capture with DMA, the filterbank (ESP-DSP FFT), the event encoder, and SNN inference in integer arithmetic.
12. **Quantise the SNN** to int8/int16 weights and integer membrane potentials (with a quantisation-aware training step), then export weights to a C header.
13. **Edge Impulse** (named in the proposal): deploy the CNN baseline through Edge Impulse to the ESP32-S3 as the conventional reference.
14. **Measure power** with a Nordic PPK2, an INA219/INA226 or a Joulescope. Report mW for quiet, factory-noise and leak-active states, for both firmware versions, with and without light sleep between events. *This produces the "Active Power Draw (mW)" metric the proposal requires.*
15. **Measure on-device detection delay**: GPIO toggle at leak start (air nozzle or valve) → GPIO toggle at alarm, measured with an oscilloscope or logic analyser.

### Priority 4: Sensor array (named in the proposal)
16. Use 2–4 microphones on the ESP32-S3 (TDM/PDM). The simplest useful demo is **channel fusion** (OR/AND voting gives fewer false alarms). A stronger one is **direction of arrival** (GCC-PHAT, or spike-timing differences between channels) to locate the leak.
17. Extend `synth.py` to simulate several channels with time delays and attenuation.

### Priority 5: Real validation data
18. Record your own small ultrasonic dataset: compressed-air nozzle or valve leaks at several pressures and distances, with recorded workshop background noise and **no-leak** segments. Even 30–60 minutes is enough to validate the results from synthetic data.
19. Reframe GPLA-12 as a robustness check (pressure classification under noise) and state its limits clearly: no negatives, not ultrasonic.

### Priority 6: Packaging and writing
20. `requirements.txt` (pinned), `.gitignore`, a `Makefile` or single `run_all.sh`, and a few unit tests (encoder quiet when no leak is present, metric functions).
21. Update the README beyond "Step 1": final results table, figures and a hardware section.
